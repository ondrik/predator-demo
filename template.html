Predator · shape analysis for C

Finding memory bugs in C programs
with linked lists

Use after free, leaks, double frees and out-of-bounds writes often hide in pointer-heavy code: list traversals, error paths, kernel-style intrusive lists. Predator is a static analyser that runs inside GCC as a plug-in. It explores all executions of a program, including lists of any length, and either reports a memory error or verifies that there is none.

How it works

  1. Compile as usual. Predator is loaded into GCC with -fplugin=libsl.so and analyses GCC's intermediate code, so it understands the same C as your compiler, macros and all.
  2. Execute symbolically. Starting from main, Predator runs the program on symbolic memory graphs: heaps in which each block has a known size and each pointer a known target and offset. Unknown input, written __VERIFIER_nondet_int() below, makes it follow both branches of every condition that depends on it.
  3. Abstract unbounded lists. A loop that allocates nodes produces ever longer lists. Predator folds a chain of similar nodes into a list segment that stands for any number of them, so the analysis reaches a fixed point after a few iterations.
  4. Check every step. Each dereference, free and assignment is checked for invalid pointers, out-of-bounds offsets and blocks that just became unreachable (leaks). No error means the property holds for all runs of the program.

Why not just run Valgrind or AddressSanitizer?

Dynamic checkers are excellent, but they see only the executions you run. All of the bugs above need a particular path: a list of the right length, a malloc that fails, a parser that gives up. If no test takes that path, the bug survives. Predator checks every path symbolically, so when it reports no errors, the fix is correct for all inputs, not only for the ones in the test suite.

The price is scope. Predator analyses whole sequential programs, and its abstraction is built for linked data structures: singly, doubly and cyclic lists, lists of lists, and lists embedded in other structures. Its precision is byte-level: block sizes, field offsets, pointer arithmetic, memset and memcpy, address alignment. Predator and its successor PredatorHP have won several medals in the memory-safety categories of SV-COMP.

Want to try it on your own code? Build it from kdudka/predator (./switch-host-gcc.sh /usr/bin/gcc), then run gcc -fplugin=sl_build/libsl.so -S -o /dev/null file.c. More details are on the project page and in the paper Byte-Precise Verification of Low-Level List Manipulation (SAS 2013). All programs from this page are in cases/.
