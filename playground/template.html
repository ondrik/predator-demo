Write or paste a C program and run Predator on it. Clang and Predator are compiled to WebAssembly and run in your browser, so your code never leaves your computer. The first run downloads the analyser (about {{SIZE}}, cached afterwards). Use __VERIFIER_nondet_int() for unknown input: Predator follows both outcomes of every condition that depends on it.

.dot

Predator's symbolic heap at that point, drawn by Predator. Boxes in dashed clusters are memory blocks with their fields; red clusters are list segments that stand for lists of any length (SLS: singly linked, DLS: doubly linked, with the minimal length, e.g. 1+); ellipses are pointer values. To see the heap at any line, declare void __VERIFIER_plot(const char *, ...); and call __VERIFIER_plot("name"); there.

Good to know

  • This is Predator's LLVM front-end: clang 14 compiles your program to LLVM IR for x86-64, and Predator analyses that. The examples on the main page were recorded with the GCC plug-in. Both report the same errors on them; column numbers can differ slightly.
  • Predator analyses a whole program starting from main. Functions without a body (other than the C library functions Predator knows) are treated as unknown, and Predator says so.
  • The standard C headers come from musl. Predator's own builtins (__VERIFIER_plot, ___sl_error, …) are available from #include <verifier-builtins.h>.
  • The analysis can take long, or not terminate, on programs outside Predator's scope: large arrays indexed by unknown values, arithmetic-heavy loops, trees. Stop cancels it.
